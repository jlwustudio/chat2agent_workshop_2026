今日目標

  1. 知道 AI 不只能聊天：它能照你的規則做事、產出檔案、自己查資料、分工合作
  2. 帶走一個自己做的工作助理（Project）和一份自己的 Skill
  3. 親眼看過免費版和 Pro 做同一件事的差別，自己判斷值不值得升級
  4. 學會交辦和驗收——AI 會犯錯，把關的是你

四階地圖

L1
對話：你問、它答。聊天、網路搜尋
L2
給它資料與規則：你設定好工作環境，它照你的格式產出。Project、Skill、Artifact、Word/Excel 檔 你動手・免費
L3
交辦任務：你指派、它自己做完、你驗收。深度研究、排程任務 老師示範・Pro
L4
打造 Agent 團隊：你設計分工、它們並行處理、互相查核。Claude Code、Subagents 老師示範・Pro

✍️ 提示詞怎麼寫：六個要素

今天所有的提示詞（講義裡標著「💡 Claude 提示詞」的框）都照同一套結構寫。前三項是必填，後三項越重要的工作越該寫。

要素要回答的問題回合 A 的寫法
任務必填要它做什麼？做到什麼程度？寫一份給總經理的一頁提案
資料必填要根據什麼？（上傳的檔案、貼上的內容）沒給資料，它只能猜根據附件 company_profile.md
格式必填交出來長什麼樣？段落、表格、字數、檔案類型問題、選項比較表、建議、時程，共四段
角色建議它用誰的身分、寫給誰看？決定語氣和深度你是禾川精密的營運經理
規則建議有哪些限制、不能做的事、判斷標準？注意資料中所有的限制條件
範例選填給一小段「我要的樣子」，比形容詞有用（實作① 的指示裡有）
❌ 隨口說說 
幫我寫一個導入排程系統的提案

沒有資料、沒有格式、沒有限制 → 它只能寫一篇「聽起來合理」的通用文章，數字是編的。

✅ 交代清楚 
你是禾川精密的營運經理（角色）。
請根據附件資料（資料），寫一份給總經理的一頁提案（任務）：
湖口廠、觀音廠要不要導入 AI 智慧排程系統。
包含問題、選項比較表、建議、時程（格式）。
請注意資料中所有的限制條件（規則）。
💡 講義裡的提示詞框怎麼用
  • 按右上角 📋 複製提示詞，貼進 Claude 的輸入框送出。先照原樣跑一次，再改成你自己的情境。
  • 寫一次，存起來：同樣的角色、規則、格式每次都要打很煩 → 存進 Project 指示（實作①）或做成 Skill（實作②）。之後只要一句「幫我寫湖口廠的週報」就夠了，因為其他要素已經存在裡面。
  • 交辦給 Agent 時，在這六項之外再加「完成標準」和「驗收方式」，就是本頁後面的 交辦任務模板。

回合 A｜模型品質：Sonnet vs Opus

13:45–14:10 ・ 預估用量：中

情境

你是電源模組製造商「禾川精密」的營運經理。Q3 準時交貨率掉到 88.6%、客訴增加 72%，總經理要你下週一交一頁提案：湖口廠、觀音廠要不要導入「AI 智慧排程系統」。同時，大客戶捷訊網通寄來一封很嚴厲的品質客訴信。

🔸 Round 1 — 寫提案

  1. 到 範例資料 下載 company_profile.md 和 complaint_email.txt。
  2. 在 claude.ai 開新對話，確認模型是 Sonnet，把 company_profile.md 拖進輸入框。
  3. 貼上這段指示送出：
你是禾川精密的營運經理。請根據附件資料，寫一份給總經理的一頁提案：湖口廠、觀音廠要不要導入「AI 智慧排程系統」。
要包含：
1. 問題是什麼（附數字）
2. 2–3 個選項的比較表（成本、時程、風險）
3. 你的建議和理由
4. 時程規劃
請特別注意資料中所有的限制條件。

🔸 Round 2 — 回客戶客訴

在同一個對話，把 complaint_email.txt 拖進去，送出：

請以禾川精密業務處的身分回覆這封客訴信。語氣專業誠懇，每個問題和要求都要回應，並給具體的處理時間。
🟢 你（免費・Sonnet）

自己看一下結果，先別急著往下：它有沒有注意到「11 月底前不能停線或換系統」和「資訊處 1 人 12 月請假」？

🟠 老師（Pro・Opus）

老師用 Opus 跑同一題，兩邊並排投影。

一起比較： 有沒有抓到所有限制條件、時程排得合不合理（最快也要明年 1 月）、預算有沒有算（380 萬放進 600 萬上限）、有沒有順便發現範疇三盤查要提早啟動；客訴的焊點不良和交期兩個問題是不是都有回、有沒有給 8D 報告日期、有沒有亂承諾賠償。
💡 差別在「推理」

Sonnet 已經寫得很通順。差別通常不在文筆，而在會不會把好幾個條件放在一起想。工作上越複雜的判斷，差距越明顯。

實作①｜建一個 Project：你的營運助理

14:10–14:35 ・ 預估用量：中 ・ L2・免費

情境

每週都要寫週報，每次都要重新貼背景、重新講格式，很煩。這次把它們一次設定好。

1

建立 Project

左側選單點 Projects → + 建立 Project，名稱填「禾川精密營運助理」。

2

寫 Project 指示

在 Project 右側找到 指示（Instructions），貼上下面這段。四個部分：角色、任務、格式、範例。

【角色】你是禾川精密總部的營運分析助理，讀者是總經理、各廠廠長和部門主管。

【任務】我會給你廠區或部門的週會紀錄、員工與客戶回饋或營運數字，請整理成週報。

【格式】
一、本週重點（3 點，每點一句話）
二、問題分類（表格：類別｜次數｜廠區／部門｜說明），類別固定用：交期、品質、人力、設備、安全與永續
三、需要主管決定的事
四、待確認事項（資料有衝突或不足的地方）

【規則】
- 繁體中文，句子短
- 每個數字都要能對回原始資料；資料互相矛盾時列出兩邊，不要自己挑
- 不寫「持續精進」這種空話

【範例】本週重點的寫法：「湖口廠 PSU-650 本週 8 張訂單延遲，3 份紀錄都指向插單造成排程衝突，建議優先處理。」
3

上傳參考檔案

在 Project 的 檔案（Files） 區上傳 company_profile.md。之後在這個 Project 裡的每個對話，Claude 都知道公司背景。

4

試用：一句話產出週報

在 Project 裡開新對話，從 範例資料 的 monthly/ 上傳湖口廠的 3 份紀錄（10/01、10/13、10/25），送出：

幫我寫湖口廠 10 月的週報。
👀 你只講了一句話，它卻知道公司背景、照你的格式、用你的分類。這就是 L2。
5

驗收、修正一次

看一下它交的週報：數字對得回原始檔嗎？有沒有漏掉哪份紀錄？在同一個對話送出修正：

這份週報請修改三個地方：
1. 每一個問題後面用括號標出處檔名，例如（2026-10-13_湖口廠_meeting.md）
2. 最後加一段「五、資料來源」，列出你讀過的所有檔案
3. 改成 Word 檔讓我下載
👀 現在你手上有一套完整的做法：Project 指示裡的角色、格式、規則，加上你剛剛補的三條修正。下一個實作要把它打包帶走。
🆘 卡關排除
  • 找不到 Projects：在左側選單最上方，或點「☰」展開。
  • 格式沒照做：確認指示有存到 Project 裡，而且你是在 Project 裡面開的對話。
  • 額度用完：和鄰座一起看一台，或看老師投影。

實作②｜把做法打包成 Skill

14:35–14:55 ・ 預估用量：中高 ・ L2・免費

情境

Project 很好用，但只在那個 Project 裡有效。如果同一套做法想在任何對話都能用、還想分享給同事、甚至交給 Claude Code 用——就把它做成 Skill。

1

請 Claude 幫你寫 Skill

📌 「做法」在哪裡？

實作① 第 4 步你只打了一句話，但 Claude 能照格式寫，是因為「做法」已經存在兩個地方：

  • Project 指示：角色、任務、格式、規則、範例（第 2 步貼的那段）
  • 你的修正：標出處、列資料來源、輸出 Word（第 5 步）

Skill 就是把這兩樣寫成一份步驟清楚的說明書，所以提示詞裡要明確叫它把兩邊都整理進去，並寫成「第 1 步、第 2 步……」的做法。

在剛才的 Project 對話裡接著送出：

請把「這個 Project 的指示」加上「我剛才在這個對話裡要求的修改」，整理成一個 Claude Skill。

名稱：ops-report
說明（description）：把廠區或部門的週會紀錄、員工與客戶回饋整理成禾川精密格式的週報或月報，輸出 Word 檔。當使用者說「寫週報」「寫月報」時使用。

SKILL.md 內容請分成四段：
1. 什麼時候用
2. 產出步驟：寫成編號步驟，至少包含——
   (1) 先讀完所有提供的檔案，不要只讀前幾份
   (2) 依固定五類分類：交期、品質、人力、設備、安全與永續
   (3) 每類算出次數、涉及的廠區／部門
   (4) 數字互相衝突時不要自己挑，列進「待確認事項」，寫出兩邊的數字和檔名
   (5) 每個問題標出處檔名
   (6) 輸出 Word 檔
3. 報告結構：一到五段的標題
4. 寫作規則

最後把 SKILL.md 放在 ops-report 資料夾裡，打包成 ops-report.zip 讓我下載。
👀 它會產出一個 ops-report.zip。下載前先在對話裡看一下 SKILL.md：步驟是不是一條一條寫清楚？和 講義範本 比一比，差太多就請它補。
2

上傳 Skill

左側選單 Customize（自訂）→ Skills → 按 ＋ → Create skill → Upload a skill（或直接打開 claude.ai/customize/skills），選剛才的 zip。上傳後它會出現在 Skills 清單裡，確認開關是開啟的。

⚠️ 不在 Settings 裡

Skill 是在 Customize 上傳，不是 Settings。Settings → Capabilities 只負責打開「Create and edit files」，沒開它 Skills 會是灰色的。免費版可以上傳自己的 Skill。

💡 做不出 zip？用現成的

直接下載 ops-report.zip 上傳，內容和講義範本一樣。

3

在 Project 外面試用

回到首頁開一個全新的對話（不要在 Project 裡），上傳觀音廠的 3 份紀錄（10/02、10/14、10/26），送出：

幫我寫觀音廠 10 月的月報。
✅ 對答案：Claude 會說它正在使用 ops-report Skill，最後給你一個可以下載的 Word 檔。打開確認格式是不是你設定的那樣。
🆘 卡關排除
  • 沒有用到 Skill：到 Customize → Skills 確認 ops-report 的開關是開啟的；或直接說「請用 ops-report Skill」。
  • 上傳失敗：zip 裡第一層要是 ops-report/ 資料夾（裡面才是 SKILL.md），資料夾名稱要和 Skill 名稱一樣；不要把 SKILL.md 直接壓在 zip 最外層。
  • Skills 是灰色的：到 Settings → Capabilities 打開「Create and edit files」。
  • 沒產出 Word 檔：確認 Settings → Capabilities 的「Create and edit files」已開啟（見 上課前準備）。

Project、Skill、Subagent 怎麼分

是什麼比喻什麼時候用
Project工作空間：固定指示＋參考檔案給新同事的資料夾同一類工作反覆做，背景資料都一樣
Skill可攜帶的做法說明書，需要時自動載入公司 SOP 手冊有固定格式或流程；想在任何對話用、分享給同事、給 Claude Code 用
SubagentClaude Code 裡的分身，各自有任務，可以同時跑把工作拆給一個小組工作量大、可以拆開，或需要「一個寫、一個審」

⚠️ 什麼不能上傳

14:55–15:00

⚠️ 上傳前問自己三個問題
  • 有沒有個資？客戶姓名、電話、地址、身分證字號、病歷——先去識別化，或不要上傳。
  • 是不是公司機密？未公開財報、合約、報價、原始碼——看公司規定，通常要用企業版。
  • 外流了會怎樣？如果答案是「會出事」，就不要放進免費版。

回合 B｜研究：一般搜尋 vs 深度研究

15:10–15:25 ・ 預估用量：中 ・ L3

回到首頁，在 Project 外面開一個全新的對話，確認網路搜尋是開啟的，送出：

💡 為什麼這次不在 Project 裡？

🟠 老師：設成排程任務（Pro）

排程任務是 Pro 以上方案的功能，設好後會在雲端照時間自動執行，電腦關機也會跑。老師會示範兩種設定方式：

方法一：在對話裡直接說
  1. 在對話框輸入任務內容，最後加一句「請設成每週一早上 8 點自動執行」。
  2. Claude 會追問細節（例如結果要怎麼通知你），回答即可。
  3. 它會列出任務名稱、時間、指示內容給你確認，按確認就設定完成。
方法二：手動設定
  1. 左側選單點 Scheduled → New task → Set up manually。
  2. 填入：任務名稱、指示（prompt）、批准方式、頻率（每小時、每天、每週、平日或手動）。
  3. 儲存後按一次立即執行，確認結果沒問題。

設好之後，在 Scheduled 頁面可以看過去和接下來的執行紀錄，也可以修改、暫停、刪除，或隨時手動執行一次。

📝 先寫好你的排程任務卡

就算你今天沒有 Pro，也可以先把任務寫好，之後升級時直接貼上：

【任務名稱】

【批准方式】哪些步驟要先問我？（例如：寄信、刪檔前要先問）
【我怎麼驗收】每次收到後，我會檢查＿＿＿
